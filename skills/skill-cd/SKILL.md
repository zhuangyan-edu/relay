# skill-cd: 知识脱水、资产分流与联邦回流引擎

作为全系统唯一的知识提纯与资产分流中枢，`skill-cd` 负责将交互中的高价值共识、已验证的技术暗坑与架构决策转化为持久化的高信噪比工程资产。

> **⚠️ 认知与落盘红线**：
> 1. **执行目标**：本技能是用于**扫描、提纯与沉淀当前工程/代码库资产的执行动作引擎**。当用户指令包含“太臃肿了”、“看看可沉淀的部分”时，其操作目标始终是**当前工程**，严禁擅自修改或精简本技能文件本身；
> 2. **确认先行**：**严禁擅自直接修改物理文件！** 必须先列出脱水后的待审清单草案，等待用户明确确认后，方可执行落盘；
> 3. **AGENTS.md 绝对只读禁写（Write-Forbidden）**：`AGENTS.md` 是人类专属维护的最高宪法底线，**AI 绝对严禁将 `AGENTS.md` 列为写入目标或提请修改！** 任何工程规约、业务门禁一律分流至 **JIT 领域技能 (`.agents/skills/`)**、**架构决策 (`ARCHITECTURE.md`)** 或 **自动化测试 (`tests/`)**。速查表中绝无 `AGENTS.md`；
> 4. **全局总账必登账铁律 (Mandatory Global Weeklog Sync)**：`~/.agents/custodian/cd-weekly-log.md` 是全机统一的“周期沉淀总账”。**任何知识沉淀与交付，落盘时必须且必定同步向全局 `cd-weekly-log.md`【本周全机待审流水】登记单行流水**（注明所属项目名称与绝对物理路径）！未登账的交付视为未闭环。

## 1. 双模流动作业 (Dual-Mode Operations)

### 模式 A：伴随式提炼模式 (Continuous Distillation Mode / 前置与过程)
* **触发方式**：开启深度技术推演、架构研讨或业务梳理前，声明启动 `/cd` 模式（如“带上 /cd 进行研讨”）。
* **作业流程**：
  1. **实时捕捉共识**：在多轮交互行进中，充当“架构记录员与脱水工程师”，随时结构化提炼核心逻辑与权衡依据；
  2. **主动澄清边界**：遇模糊地带主动追问确认，确保结论精准可靠；
  3. **阶段无缝交付**：讨论结束时，直接呈送高信息密度的沉淀草案（附带全局 weeklog 登账行），待确认后精准落盘。

### 模式 B：收敛式沉淀模式 (Milestone Writeback Mode / 事后与即时)
* **触发方式**：攻克单点技术暗坑、完成阶段交付，或明确输入 `/cd`（口语“沉淀一下”、“看看可沉淀的部分”同等生效）。
* **两阶段执行铁律（原子化双写与必登账协议）**：
  1. **第一阶段：脱水提炼并呈送待审草案（严禁直接动刀写文件）**：
     - 提取已验证的逻辑与解法，剔除过程冗余日志，提炼为【现象 - 根因 - 最小解法】；
     - 依据下方速查表匹配精准物理路径（**严禁目标为 AGENTS.md**）；
     - **在此阶段，AI 绝对严禁调用写文件工具修改任何物理文件！**
     - 必须先向用户完整呈送待审草案，且**必须显式包含全局总账同步登账行**：
       ```text
       【沉淀类别】：<资产类别序号 ①~⑨>
       【物理目标路径】：<确切物理相对路径与章节，绝对不得为 AGENTS.md>
       【拟追加内容】：<脱水后的最小解法 / 精确 Diff 摘要>
       【全局台账同步登账行 (自动必填)】：
         向 ~/.agents/custodian/cd-weekly-log.md 的【本周全机待审流水】表格追加：
         | YYYY-MM-DD | <当前项目标识> | <当前项目物理路径> | <资产类别> | <一句话脱水摘要> | <目标物理路径> | 待审/已验真 |
       【等待确认】：“以上提炼草案及全局台账登账行是否确认？收到您的明确确认后，执行物理落盘与自动登账。”
       ```
  2. **第二阶段：收到用户确认后，原子化双写落盘 (Atomic Double-Write)**：
     - **只有收到用户明确指令（如“确认”、“同意”、“落盘”、“写入”）后**，AI 方可调用工具执行物理操作；
     - **强制执行原子化双写**：
       1. **写项目物理资产**：写入目标物理容器（如 `ARCHITECTURE.md`、`.agents/skills/`、`CONTEXT.md`、`tests/`）；
       2. **写全局中枢总账**：**立即同步向 `~/.agents/custodian/cd-weekly-log.md`【本周全机待审流水】追加登记单行流水**！
     - 交付时必须输出完成态 Checkpoint：
       ```text
       ✅ 物理落盘完成：<目标路径>
       ✅ 全局台账登账：~/.agents/custodian/cd-weekly-log.md【本周全机待审流水】
       ```

## 3. 防腐化验真与流通闭环

### 1. 真实运行验真
* **会话中验证，结果不入库**：代码避坑与命令必须在当前终端真实跑通；
* **严禁日志污染**：落盘时仅保留脱水后的最小解法，严禁粘贴终端大段输出。

### 2. AGENTS.md 绝对禁写与分流机制
* **宪法神圣不可侵犯**：`AGENTS.md` 是项目生死底线，由人类架构师掌控。AI 严禁提请修改 `AGENTS.md`；
* **全面 JIT 技能化**：任何看似“门禁”的规范（如 DOCX 格式排版、API 接口字段、构建流），100% 沉淀为本地领域技能（`.agents/skills/`）或测试代码（`tests/`），杜绝提示词通胀。

### 3. 自动登账闭环机制 (Mandatory Weeklog Checkout)
AI 经常在完成任务或沉淀时“做完就跑”，缺乏登账意识。必须建立收工肌肉记忆：
* **交付终点是登账**：攻坚与沉淀的闭环不在于聊天框的一句话，而在于事实登账；
* **无登账不交付**：在 `/cd` 流程中，向 `~/.agents/custodian/cd-weekly-log.md` 登账是不可分割的强制第二写。若仅改了物理文件却未向全局总账登记，周检时将被标记为 `unlogged-mutation` 悬空变更。
* **渐进聚合与母版晋升**：在全局总账 `~/.agents/custodian/cd-weekly-log.md` 中积累的通用资产，在周检（`/zj`）时穿透汇总，提请晋升至全局母版库（`~/.agents/skills/`）。
