# skill-cd: 知识脱水、资产分流与联邦回流引擎

作为全系统唯一的知识提纯与资产分流中枢，`skill-cd` 负责将交互中的高价值共识、已验证的技术暗坑与架构决策转化为持久化的高信噪比工程资产。

> **⚠️ 认知与落盘红线**：
> 1. **执行目标**：本技能是用于**扫描、提纯与沉淀当前工程/代码库资产的执行动作引擎**。当用户指令包含“太臃肿了”、“看看可沉淀的部分”时，其操作目标始终是**当前工程**，严禁擅自修改或精简本技能文件本身；
> 2. **确认先行**：**严禁擅自直接修改物理文件！** 必须先列出脱水后的待审清单草案，等待用户明确确认后，方可执行落盘。

## 1. 双模流动作业 (Dual-Mode Operations)

### 模式 A：伴随式提炼模式 (Continuous Distillation Mode / 前置与过程)
* **触发方式**：开启深度技术推演、架构研讨或业务梳理前，声明启动 `/cd` 模式（如“带上 /cd 进行研讨”）。
* **作业流程**：
  1. **实时捕捉共识**：在多轮交互行进中，充当“架构记录员与脱水工程师”，随时结构化提炼核心逻辑与权衡依据；
  2. **主动澄清边界**：遇模糊地带主动追问确认，确保结论精准可靠；
  3. **阶段无缝交付**：讨论结束时，直接呈送高信息密度的沉淀草案，待确认后精准落盘。

### 模式 B：收敛式沉淀模式 (Milestone Writeback Mode / 事后与即时)
* **触发方式**：攻克单点技术暗坑、完成阶段交付，或明确输入 `/cd`（口语“沉淀一下”、“看看可沉淀的部分”同等生效）。
* **两阶段执行铁律（严禁直接修改，必须先列清单待确认）**：
  1. **第一阶段：脱水提炼并呈送待审草案（严禁直接动刀写文件）**：
     - 提取已验证的逻辑与解法，剔除过程冗余日志，提炼为【现象 - 根因 - 最小解法】；
     - 依据下方速查表匹配精准物理路径；
     - **在此阶段，AI 绝对严禁调用写文件工具修改任何物理文件！**
     - 必须先向用户完整呈送待审草案：
       ```text
       【沉淀类别】：<资产类别序号 ①~⑧>
       【目标路径】：<确切物理相对路径与章节>
       【拟追加内容】：<脱水后的最小解法 / 精确 Diff 摘要>
       【等待确认】：“以上提炼草案是否确认？收到您的明确确认后，再行物理落盘与登账。”
       ```
  2. **第二阶段：收到用户确认后，方可物理落盘 (Human-Confirmed Writeback)**：
     - **只有收到用户明确指令（如“确认”、“同意”、“落盘”、“写入”）后**，AI 方可调用工具将内容写入目标文件；
     - 落盘完成后，自动在当前项目的 `.agents/cd-weekly-log.md` 追加单行待审记录，为周检提供闭环线索。

## 3. 防腐化验真与流通闭环

1. **真实运行验真**：
   - 会话中验证，结果不入库：代码避坑与命令必须在当前终端真实跑通；
   - 严禁日志污染：落盘时仅保留脱水后的最小解法，严禁粘贴终端大段输出。
2. **渐进聚合与母版晋升**：
   - 单点项目中沉淀出的通用工具与高频规则，由 `skill-weekly-custodian`（周检 `/zj`）汇总；
   - 具备跨工程普适价值的，主动提请晋升至全局母版库（`~/.agents/skills/`），全机共享免疫抗体。
