# skill-relay: Relay 全局套件启动器与架构索引

作为 Relay 生态的全局中枢，本技能负责新项目的极简开局（`relay.py init`）以及跨 AI 宏观寻址大地图导航。

## 运行时边界

仓库内的 `relay.py` 是确定性运行时，当前实现 `init`、`audit`、`sweep` 和 `version`；安装器会将它部署到 `~/.agents/relay.py`。`/jp`、`/cd` 仍是由宿主 AI 解释执行的协作规约；全局巡检请使用 `relay.py sweep`，不应把未实现的后台调度器写成现有能力。

## 1. 触发入口与常用指令

* **开局初始化**：`relay.py init` 或对 AI 说“**用 relay 初始化项目**”；
* **架构大地图查阅**：阅读 `AI_START_HERE.md`（Heavy）或 `ARCHITECTURE.md`（Standard/Heavy）；
* **确定性巡检**：`relay.py sweep`（读取项目注册表并生成周报）；
* **三大日常指令**：
  * **`/jp`**：核心思想罗盘（前置预防 + 后置即时校准）
  * **`/cd`**：知识脱水与回写（宿主 AI 按确认协议写回并登账）
  * **`/zj`**：每周自检与保洁（查账、去日志臃肿、移云、结项）

## 2. 治理阶梯感知与开箱作业流 (`relay.py init`)

### 核心铁律：初始化范围明确且可审计 (Scoped Initialization)
1. **运行时只触碰声明范围**：`relay.py init` 仅写当前项目的选定模板，并将本项目登记到 `~/.agents/custodian/projects.json`；不会隐式改写其他客户端配置。
2. **首次使用时说明选择**：若全局目录尚未存在，宿主 AI 可以向用户展示三级治理阶梯（1.单项目独立 / 2.全机项目总控 / 3.全局 AI 配置统管），但未经确认不得代为安装全局配置。
3. **冲突默认保留**：已有不同内容时 CLI 报告冲突并保留；只有显式 `--force` 才覆盖文件，重复初始化不会重写元数据。

### 💡 核心分流：单点痛点按需治理 vs 系统架构开箱分级

Relay 赋予开发者完全的自由度，将使用场景划分为两个清晰的维度：

#### 维度一：存量工程单点痛点按需治理 (On-Demand Capability - 拒绝强制重构)
若现有项目不想改变整体架构，仅想解决某一特定恶疾，可随时单独按需调用对应机制，互不强求：
1. **只治“粉象回潮与防御内耗”** ➔ 仅引入 2 行微内核宪法，或在 AI 内耗时输入 `/jp` 纠偏，零文件变动；
2. **只治“多项目同步地狱”** ➔ 仅在根目录放单行指针指向 `~/.agents/PHILOSOPHY.md`，实现思想全局同频；
3. **只治“业务文档肆意污染”** ➔ 仅建立 `.agents/` 目录收敛 Agent 自检台账，草稿入 `scratch/`，将 `docs/` 100% 归还业务；
4. **只治“提示词恶性通胀”** ➔ 仅把膨胀的流程规则外化为带 YAML Frontmatter 的 `.agents/skills/`，平时 0 Token，按需 JIT 读入。

#### 维度二：工程开局架构规格分级 (Architectural Tiers - 依据系统复杂度深度分化)
若执行 `relay.py init` 确立或重构项目架构，则依据该工程本身的**系统拓扑、模块解耦深度与生命周期复杂度**，选择对应架构形态（三者在架构深度上有着本质差异，绝非简单积木相加）：

* **规格 A：Lite（单文件微内核架构 · 极简轻装）**
  - **适用场景**：单脚本小工具、CLI 自动化脚本、短期个人实验或独立原型；
  - **架构本质**：**单文件闭环**。仅在根目录生成 1 个 `AGENTS.md`（极简 10 行，微内核 + 全局单向指针）。无 `docs/`，无 `.agents/`，零结构负担，即建即跑。
* **规格 B：Standard（四顶层资产与生命周期治理架构 · 标准工程 - 官方推荐）**
  - **适用场景**：常规商业化应用、前后端分离工程、全栈 Web/移动端、有持续版本迭代的独立项目；
  - **架构本质**：**四大顶层独立资产分立 + 生命周期闭环**。
    1. 顶层分工：`AGENTS.md`（宪法底线）+ `ARCHITECTURE.md`（拓扑与集中 ADR）+ `CONTEXT.md`（纯净业务事实）+ 全局单真理源 `PHILOSOPHY.md`；
    2. 物理秩序：`docs/` 100% 留给用户 PRD，`.agents/` 收揽周检台账（`cd-weekly-log.md`）、专名字典（`proper-nouns.md`）与云归档指针（`cloud-archive.md`）；
    3. 运行支撑：打通基于 `/cd` 的会话知识脱水与基于 `/zj` 的定期审计保洁。
* **规格 C：Heavy（多域强防腐边界与宏观路由架构 · 工业级大型系统）**
  - **适用场景**：企业级 Monorepo、多产品挂载复杂系统（如“理论决策研究 + 交付软件平台”双产品挂载）、跨域大型科研仿真工程；
  - **架构本质**：**多域强防腐边界 + 宏观多入口路由 + 专有领域扩展技能挂载**。在 Standard 基础上追加：
    1. **多域强防腐边界与交付红线 (`docs/product-boundary.md`)**：明确定义多产品/多模块间的挂载关系、决策链防线与能力真伪防线，严禁跨域造假与越权串味；
    2. **多入口宏观路由大地图 (`AI_START_HERE.md`)**：为跨 AI 异步团队提供全局入口指引，根治大型项目新接手 AI“盲人摸象”的深层迷航；
    3. **本地专属领域扩展技能 (`.agents/skills/`)**：挂载当前工程专属的高壁垒领域工具（如核算门禁、空间建模、仿真套件），依托标准 JIT 规范实现复杂规约的渐进式按需加载。

## 3. 为项目建立“规则物理资产化与 JIT 双模分流”架构 (Architecture Provisioning)

当执行 `relay.py init` 或存量接入时，AI **不仅是创建空文件，必须确定性地为该项目完成四大架构闭环**：

1. **规则物理资产化 (Rule Externalization)**：
   - 严禁将大段开发规范、命令说明、测试约束塞入系统提示词或 `AGENTS.md`；
   - 技术栈拓扑与架构决策拆入 `ARCHITECTURE.md`；
   - 业务事实与功能状态拆入 `CONTEXT.md`；
   - 领域专有流程与工具门禁拆入 `.agents/skills/<domain-name>/SKILL.md`；
   - 临时排错草稿收敛至 `scratch/`；
   - `AGENTS.md` 仅保留不可逾越的生死底线（本项目核心规约）。
2. **极简微内核单向指针 (Microkernel One-Way Pointer)**：
   - 在新项目的 `AGENTS.md` 中必装【寻址与协同】单向指针节；
   - 仅用单行指针链接外部资产，全局常驻上下文开销严格限制在 50~100 Tokens 之间。
3. **轻量元数据索引与按需动态载入 (Progressive JIT Loading)**：
   - 项目专有技能遵循 YAML Frontmatter 标准元数据规范（`name` + `description`）；
   - 平时仅向环境暴露一句话触发条件（30 Tokens），完整规约正文平时**绝不常驻注入**（0 Token 开销）；
   - 只有触发时才通过文件读取工具 JIT 动态读入，用完即退。
4. **显式命令路由与隐式意图匹配清晰分流 (Dual-Mode Dispatch)**：
   - **显式确定性指令**：`/relay`、`/jp`、`/cd`、`/zj` 走前缀命令路由，确定性 100%，严格执行两阶段确认先行；
   - **隐式情境意图匹配**：项目本地领域技能（如接口门禁、数据质检、仿真运行）依据上下文意图自动激活，无需用户背诵复杂命令。

## 4. 存量项目接入与无损重构铁律 (Lossless Inheritance Protocol)

当对存量成熟项目引入 Relay 或进行架构升级时，**严禁暴力清空与教条式抹除**，必须严格遵循以下保护铁律：

1. **项目唱主角：自主提炼核心规约 (Project Invariants)**：
   - `AGENTS.md` 严禁机械套用死板插槽，必须由该项目根据自身业务本质与技术栈，自主提炼关键的生死底线（不设条数与行数配额），展现项目自身特色；
2. **历史沉淀必须索引清晰 (Epoch Indexing Protocol)**：
   - 历史长文档与开发日志移云沉淀时，严禁腰斩式粗暴截断；必须在活跃文档头部维护【历代里程碑归档全景索引表】，确保演进脉络第一屏一览无余；
3. **合理索引梯级承接**：
   - 顶层 `AGENTS.md` 保持精炼，按需书写，字字管用，杜绝空洞套话；
   - 未入常驻宪章的细则严禁丢弃，按需编入文档或路由大地图，确保可清晰追溯。
4. **尊重并保护本地独占技能**：
   - 本地 `.agents/skills/` 中的专用领域工具（如核算、空间建模、仿真套件）是关键资产，通用全局技能只作为底座外挂，严禁粗暴删除本地专用技能包；
5. **杜绝矫枉过正，不走反面极端**：
   - 当用户提出反向否定（如“不要某物”、“太繁琐”、“削减某项”）时，精准识别否定边界，只切除多余杂质并稳守有效基石，坚决杜绝因被否定而过度反应、滑向对立极端的二极管摆动；
6. **独立客观，不盲从迎合**：
   - 立足技术事实与代码真相，不因用户的主观推测或倾向性建议而盲从附和，敢于直言指出技术隐患，做负责任的工程搭档。
