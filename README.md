# Relay 🏃‍♂️

> **The Minimalist, Zero-Overhead, Self-Evolving Agent Framework for Relay Coding.**  
> 面向跨 AI（Claude / Cursor / Gemini / Codex / GPT / WorkBuddy）异步接力与自进化的极简敏捷工程套件。

> `Version: 1.0.0 (内测中)` · `License: MIT` · `AI-Native: Claude | Cursor | Gemini | Codex | WorkBuddy` · `Philosophy: Affirmative & Lossless`

---

## 💡 为什么诞生 Relay？

在现代 AI 辅助编程与跨模型异步协作中，开发者普遍遭受四大结构性折磨：

1. **粉象回潮与防御内耗**：系统提示词充斥着“严禁做X”、“冷酷审视”、“严禁谄媚”等反向禁令，负向催眠诱发大模型陷入自我怀疑与防御性内耗，光写免责辩解却迟迟不交付代码；
2. **多项目同步地狱**：每个项目根目录都拷贝一份大同小异的规范文件；一旦原则演进，必须手动去同步本机数十个代码库，极易产生时空错位与标准分裂；
3. **提示词恶性通胀**：把工具配置、沙盒说明、甚至是项目说明一股脑塞进全局系统提示词，白白浪费上下文 Token，还给 AI 套上沉重的思维枷锁；
4. **业务文档被肆意污染**：AI 的自检流水账、技术排错日记、专有名词映射表被粗暴塞入 `docs/`，与用户原本干净的需求文档、PRD 和 `.docx` 严重撞车冲突。

**Relay（接力）用一套极其克制的“全局单真理源 + 极简微内核 + 物理隔离 + 双中枢托管”架构，彻底击碎以上乱象，让代码库与跨 AI 团队像传接力棒一样流畅自进化。**

## 🧭 三级治理阶梯：把系统全局配置的决定权交给用户

Relay **绝不仅是单个项目的初始化脚手架，更是统管全电脑所有项目与跨 AI 客户端的治理中枢**。

但我们坚守实效权衡，坚决杜绝“全家桶式强行捆绑”——是否接管全局配置，选择权 100% 属于用户：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        用户自主裁决的三级治理阶梯                       │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 3：系统全局配置托管 (Global System & AI Alignment)                │
│   • 一体化搞定全机 6 大 AI 客户端（Claude/Cursor/Codex 等）系统提示词  │
│   • 部署全机单真理源 ~/.agents/PHILOSOPHY.md 与全局共享技能库          │
│   • 用户裁决：是否授权 Relay 一并托管并对齐全机 AI 全局配置？           │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 2：全机项目资产总控 (Machine-Wide Portfolio Custody)              │
│   • 盘点全电脑所有工程，统一登记入 ~/.agents/custodian/projects.md     │
│   • 周检 (/zj) 站在全机高度，穿透所有项目做防腐保洁、跨库暗坑聚类、移云│
│   • 无论项目在 C 盘、D 盘还是其他目录，全盘资产一目了然                │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 1：单项目轻装接入 (Single Project Isolation)                      │
│   • 仅对当前单次任务/小工具生成 AGENTS.md 或标准资产                   │
│   • 绝对物理隔离，不触碰电脑上其他项目，不改动任何系统全局配置         │
└────────────────────────────────────────────────────────────────────────┘
```

> **⚡ 核心铁律：全局已就绪时静默感知，绝不频繁打扰 (Silent Passthrough Protocol)**  
> - **用户已经在全局做过了？绝不每次都问！**  
> - Relay 具备全局状态自感知能力：当检测到全局中枢已就绪，后续在任何项目运行 `relay init` 时，**将自动跳过全局配置询问**，直接聚焦当前项目精准落盘，并在后台**静默自动登账**至全局 `projects.md`；  
> - 真正做到：“**全局一次搞定，日常静默无感**”。

## 🏛️ 四大独立顶层资产（各司其职，互不污染）

Relay 将工程资产做出了最高清晰度的物理切分：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        四大独立顶层资产 (Top-Level Assets)               │
├───────────────────┬───────────────────┬─────────────────┬──────────────┤
│   PHILOSOPHY.md   │  ARCHITECTURE.md  │    AGENTS.md    │  CONTEXT.md  │
│   【核心思想】    │   【系统架构】    │  【微内核宪法】 │ 【业务现状】 │
├───────────────────┼───────────────────┼─────────────────┼──────────────┤
│ 跨 AI 思考与权衡  │ 系统拓扑、技术栈  │ 极简两行微内核  │ 业务逻辑事实 │
│ 预装确立六大支柱  │ 集中收拢 ADR 决策 │ + 项目独有规约  │ 产品功能状态 │
│ 全局唯一单真理源  │ 明文 AI 维护协议  │ 零提示词通胀    │ 纯净业务事实 │
└───────────────────┴───────────────────┴─────────────────┴──────────────┘
```

1. **`PHILOSOPHY.md`（灵魂 · 全局单真理源）**：
   * 存放在全局 `~/.agents/PHILOSOPHY.md`，全机**只有这唯独一份**；
   * 预装经过实战淬炼的**六大工程核心思想**（全域受益、实效权衡、两端取优、客观求真、纯正向聚焦、融贯自洽）；
   * 本地项目绝不物理复制代码！改动 1 次全机所有项目秒级同频受益，彻底终结多项目同步噩梦。
2. **`ARCHITECTURE.md`（骨架 · 本地独享系统架构）**：
   * 项目专属技术全景，整合系统拓扑、模块依赖与前后端解耦边界；
   * **彻底消灭零碎的 ADR 碎片目录**：在一个连贯日志中集中记录选型因果（为什么选、放弃了什么、锁定了什么）；
   * 附带明文的《AI 架构维护协议》，让后续接力协作的任何 AI 都能直接、规范地就地维护架构。
3. **`AGENTS.md`（宪法 · 微内核 + 本项目核心规约）**：
   * 包含全域统一的“两行极简微内核”与“本项目核心规约 (Project Invariants)”；
   * **项目唱主角，展现自身特色**：由项目根据自身业务本质（算法边界、核心场景、契约优先、类型禁令等）自主陈述不可动摇的底线规则，字字管用，拒绝空洞套话。
4. **`CONTEXT.md`（血肉 · 纯净业务上下文）**：
   * 100% 专注业务产品逻辑、用户旅程与当前功能状态，绝不掺杂任何技术架构、工作流或 AI 内部运维杂质。

## 📜 极简微内核宪法：两行基线

为了根治提示词恶性通胀、破除负向催眠，Relay 确立了面向全机所有 AI 客户端（Claude Code、Cursor、Gemini / Antigravity、Codex、WorkBuddy）的**统一两行基线**：

```markdown
# Relay Agent Constitution

- **核心思想**：客观求真、实效权衡、两端取优、纯正向聚焦（详见 ~/.agents/PHILOSOPHY.md）。
- **接力心智**：面向跨 AI 异步团队交付持久化、可运行的代码与文档。
```

> **设计要诀**：
> 1. **原词直达**：直接使用 4 个核心思想原词，零多余排比解释，上下文消耗趋近于零；
> 2. **纯正向表达**：一字不提“严禁”，从根源消除粉象效应；
> 3. **单向指针**：将具体思想解析收敛于全局单真理源 `~/.agents/PHILOSOPHY.md`，按需深读，不占常驻提示词；
> 4. **原生人设完整保护**：有原生特色的 AI（如 WorkBuddy K2 原生人设）100% 完整保留，通用底座与领域基因有机共生。

## 🔒 物理隔离：业务归业务，Agent 归 Agent

在项目文件树中，Relay 实行严格的物理边界隔离：

```text
📁 docs/                          ──► 【100% 留给业务与用户】真实业务方案、PRD、需求文档与 docx，AI 绝不占用！
📁 .agents/                       ──► 【Agent 专属内部空间】彻底隔离内部支撑，按需建立：
   ├── cd-weekly-log.md           ──► 周期沉淀与周检审计台账（含纪元索引表）
   ├── proper-nouns.md            ──► 2~4 字专有名词字典（支持缺页自愈）
   ├── gdrive-cloud-archive.md    ──► 云归档检索墓碑表（重型资产迁出至网盘后留单行指针）
   └── skills/                    ──► 本项目专有的领域级扩展技能（按需挂载）
```

## 🌐 全局双台账中枢 (`~/.agents/custodian/`)

Relay 在用户主目录建立了面向全机所有工程与 AI 客户端的全局总控中枢：

```text
~/.agents/
├── PHILOSOPHY.md                 # 全机唯一核心思想真理源
├── custodian/                    # 【全局总控中枢】
│   ├── projects.md               # 项目注册总台账（登记全机 Relay 项目路径与状态）
│   ├── ai-agents.md              # AI 客户端监管台账（统管 Claude, Cursor, Codex 等系统提示词）
│   └── reports/                  # 历次跨项目审计周报归档 (YYYY-Wxx.md)
└── skills/                       # 全局核心驱动技能包
```

1. **`projects.md`（项目注册总台账）**：登记全机所有 Relay 项目的物理路径、体量级别（Lite/Standard/Heavy）、周报寻址与活跃状态；
2. **`ai-agents.md`（AI 客户端监管台账）**：统一监管全机 6 大 AI 客户端的提示词规范，既守牢极简底线，又保护原生特色；
3. **`reports/`（审计周报归档）**：沉淀历次全局巡检的脱水简报，事实清楚、无冗余通胀。

## ⚡ 四大核心驱动技能（指令与快捷别名）

Relay 采用统一的极简命令驱动日常工程协作，支持拼音缩写与自然中文口语双向触发：

| 指令 / 快捷别名 | 技能名称 | 核心能力与心智 |
| :--- | :--- | :--- |
| **`/relay`** 或 `relay init` | **【初始化与开箱】** | 3 秒按体量开箱；存量工程无损接入；重构铁律坚守“不破不立、无损共生”。 |
| **`/jp`** 或 `纠偏` | **【思维校准罗盘】** | **双模引擎**（前置预防 + 后置纠偏），对照正向哲学纠偏，破除非黑即白，直接输出可用代码。 |
| **`/cd`** 或 `沉淀` | **【知识脱水与回流】** | **会话严格验真**；仅提炼【现象 - 根因 - 最小解法】；**确认先行，严禁直接修改，必须先列清单让人确定**；确认后自动回写登账。 |
| **`/zj`** 或 `周检` | **【全局自检与保洁】** | 穿透全机项目；核查历史长文档纪元索引；提请完结大资产迁移云端留单行墓碑；零通胀事实汇报。 |

### 技能详细说明：
* **`/relay`（初始化与生命周期）**：无论从零新建还是存量改造，对 AI 说一声 `relay init`，自动评估工程规模，精准落盘，绝不污染已有业务源码。
* **`/jp`（思维纠偏双模引擎）**：
  - *前置预防*：启动复杂重构或深水区任务时附带 `/jp`，AI 开局即装载正向思维，客观权衡收益代价；
  - *后置校准*：发现 AI 输出出现反向辩白、教条主义或过度设计时输入 `/jp`，立即在思维链中对照正向支柱重新组织交付。
* **`/cd`（知识脱水与资产回流）**：
  - **确认先行红线**：AI **绝对严禁未经确认直接调用工具修改物理文件**！必须先呈送待审草案（类别、目标路径、拟追加内容），等待用户明确确认后，方可执行物理落盘；
  - 必须在终端实跑通过，拒绝纸上谈兵；
  - 严禁控制台日志入库，落盘仅保留极简单行或最小解法；
  - 自动向当前项目的 `.agents/cd-weekly-log.md` 登账；具备跨项目通用价值的经验提请晋升全局母版。
* **`/zj`（跨项目周巡检）**：
  - 读取 `custodian/projects.md`，按表索骥定点穿透各项目自检；
  - 维护历史纪元索引，推动大体积归档资料迁出至云盘，本地仓库仅留轻量检索指针；
  - 健康时仅汇报 2 行事实，不强造无意义的虚假改进建议。

## 🚀 3 步开箱与项目体量分级

在新项目或存量项目目录，对任何 AI 说：`用 relay 初始化项目`（或输入 `relay init`），选择体量规格，精准落盘：

| 规格级别 | 适用场景 | 落盘清单（精准可数，杜绝冗余） | 特点 |
| :--- | :--- | :--- | :--- |
| **1. Lite** | 单次爬虫、简单数据脚本、算法验证 Demo | **仅 1 个文件**：<br>`AGENTS.md`（两行微内核） | 零 docs、零多余配置，单文件轻装上阵。 |
| **2. Standard**<br>*(推荐)* | 前后端独立 Web、小程序、通用工具库工程 | **共 4 份核心资产**：<br>1. `AGENTS.md`<br>2. `ARCHITECTURE.md`<br>3. `CONTEXT.md`<br>4. `.agents/` 专属支撑套件 | 业务 `docs/` 完全留白，开箱即拥有完整自进化与接力能力。 |
| **3. Heavy** | 跨端跨学科工业级大型系统、多产品挂载平台 | **在 Standard 基础上追加**：<br>+ `docs/product-boundary.md`<br>+ `AI_START_HERE.md`<br>+ 本地 `.agents/skills/` 目录 | 严守产品边界契约，满足大型工业级系统的高复杂度协作。 |

## ⏱️ 1 分钟极速上手 (Quick Start)

只需要三步，将全机开发环境升级为 Relay 接力自进化体系：

### 第一步：克隆并部署全局中枢
将本仓库克隆至本地，将全局中枢与技能部署至用户主目录：
```bash
# 克隆 Relay 仓库
git clone https://github.com/zhuangyan-edu/relay.git

# 部署全局真理源、总控台账与技能（Windows PowerShell 示例）
mkdir -Force $HOME\.agents\custodian
Copy-Item relay\PHILOSOPHY.md $HOME\.agents\
Copy-Item -Recurse relay\custodian\* $HOME\.agents\custodian\
Copy-Item -Recurse relay\skills $HOME\.agents\
```

### 第二步：配置 AI 客户端系统提示词
在你的常用 AI 客户端（Claude Code、Cursor、Gemini、Codex 等）系统提示词或自定义规则中，加入极简微内核：
```markdown
# Relay Agent Constitution

- **核心思想**：客观求真、实效权衡、两端取优、纯正向聚焦（详见 ~/.agents/PHILOSOPHY.md）。
- **接力心智**：面向跨 AI 异步团队交付持久化、可运行的代码与文档。
```

### 第三步：在任何项目中开箱启用
进入你的工作项目目录，直接对 AI 下达指令：
```text
用 relay 初始化项目
```
AI 将根据项目体量推荐合适规格（Lite / Standard / Heavy），自动生成专属资产骨架，并自动登账至全局 `~/.agents/custodian/projects.md`！

## 🎯 核心工程哲学 (Engineering Philosophy)

Relay 坚守六大纯正向支柱（详见 [PHILOSOPHY.md](PHILOSOPHY.md)）：

1. **全域受益 (Global Benefit)**：单点突破提炼后母版同步受益，所有项目共享免疫抗体；已完结的历史重型资产规范归档云端，本地仓库轻量敏捷。
2. **实效权衡 (Pragmatic Trade-offs)**：繁简自适，按实际工程体量自主裁决复杂度；**按需建立，物尽其用，杜绝冗余**。既有容器能承载的内容直接合并，消除无价值派生文件。
3. **两端取优 (Optimal Balance & Trade-offs)**：
   * **杜绝矫枉过正，不走反面极端**：当用户提出反向否定（如“不要某物”、“太繁琐”）时，精准识别否定边界，只切除多余杂质并稳守有效基石；坚决杜绝因被否定而过度反应、滑向对立极端的二极管摆动；
   * **因地制宜，合理权衡**：不搞绝对化的非黑即白，寻求综合收益最高、副作用最小的务实解；
   * **无损继承与领域共生**：全局统一与局部特质并存，通用底座与领域基因有机共生，拒绝机械式一刀切。
4. **客观求真 (Fact-Based Objectivity)**：
   * **独立客观，不盲从迎合**：立足技术规律与客观事实，不因用户的主观推测或倾向性建议而盲从附和；
   * **以真实证据为凭据**：以代码实际运行结果与客观证据为准绳，就事论事，敢于直言指出技术隐患。
5. **纯正向聚焦 (Affirmative Delivery Focus)**：
   * **肯定陈述**：表达聚焦于系统具备的能力、客观数据与具体实施路径；
   * **直奔交付**：精力 100% 倾注于代码落地与实际推进，直接给出可用方案与运行结果，消除防御性免责与反向辩白。
6. **融贯自洽 (Dynamic Coherence)**：原则相通互保，动态统一于工程交付实效；分层索引互为闭环，让体系既清爽轻量，又事实可考。
