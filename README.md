# Relay 🏃‍♂️

> **A Markdown-first, auditable project bootstrapper and collaboration kit.**
> 面向跨 AI（Claude / Cursor / Gemini / Codex / GPT / WorkBuddy）异步接力与自进化的极简敏捷工程套件。

> `Version: 1.1.0` · `License: MIT` · `AI-Native: Markdown + standard-library CLI` · `Philosophy: Affirmative & Lossless`

---

## 💡 为什么诞生 Relay？

在现代 AI 辅助编程与跨模型异步协作中，开发者普遍遭受四大结构性折磨：

1. **粉象回潮与防御内耗**：系统提示词充斥着“严禁做X”、“冷酷审视”、“严禁谄媚”等反向禁令，负向催眠诱发大模型陷入自我怀疑与防御性内耗，光写免责辩解却迟迟不交付可用代码；
2. **多项目同步地狱**：每个项目根目录拷贝一套大同小异的规范，原则一旦更新，需手动同步全机数十个代码库，极易产生时空错位与标准分裂；
3. **提示词恶性通胀**：把工具配置、沙盒说明一股脑塞进全局系统提示词，白白浪费 80% 上下文 Token，还给 AI 戴上沉重的思维枷锁；
4. **业务文档肆意污染**：AI 把自检流水账、技术排错日志、专有名词映射表粗暴塞入 `docs/`，与用户原本干净的需求文档、PRD 和 `.docx` 严重撞车冲突。

**Relay（接力）用一套极其克制的“全局单真理源 + 极简微内核 + 物理隔离 + 双中枢托管”架构，彻底击碎以上乱象，让代码库与跨 AI 团队像传接力棒一样流畅自进化。**

## 🌟 第一部分：核心功能与确定性收益 (Capabilities & Benefits)

### 💡 两大使用维度：单点痛点按需借用 vs 系统开局架构分级

Relay 赋予开发者完全的工程自由度，坚决反对将复杂架构粗暴降维为简单的积木算术累加。Relay 将使用场景清晰划分为两个独立维度：

#### 维度一：存量工程单点痛点按需借用 (On-Demand - 拒绝强制推倒重来)
如果您的现有项目不想推翻现有架构，仅想借用 Relay 消除某一特定恶疾，完全可以单点按需选用：
* **只治“粉象回潮与防御内耗”** ➔ 仅引入 2 行微内核宪法，或在 AI 陷入免责辩解时敲 `/jp` 纠偏，0 物理文件改动；
* **只治“多项目同步地狱”** ➔ 仅在根目录放单行指针链接全局 `~/.agents/PHILOSOPHY.md`，实现多工程思想全局同频；
* **只治“业务文档肆意污染”** ➔ 仅建立 `.agents/` 目录收拢 AI 运维台账，草稿入 `scratch/`，将 `docs/` 100% 完整留给业务 PRD；
* **只治“提示词恶性通胀”** ➔ 仅将冗长的规则外化为 `.agents/skills/`，通过 YAML Frontmatter 声明极简元数据，激活时 JIT 按需读入。

#### 维度二：系统开局三大架构分级 (Architectural Tiers - 依据系统复杂度深度分化)
如果您准备通过 `relay.py init` 为新项目奠定架构底座（或对成熟工程进行系统化重构），则依据工程本身的**系统拓扑、解耦深度与生命周期复杂度**，选择对应架构形态（三者在架构深度上有着本质差异）：

* **规格 A：Lite（单文件微内核架构 · 极简轻装）**
  - **适用场景**：单脚本小工具、CLI 自动化脚本、短期个人实验或独立原型；
  - **架构本质**：**单文件闭环**。仅在根目录生成 1 个 `AGENTS.md`（极简 10 行，微内核 + 全局单向指针）。无 `docs/`，无 `.agents/`，零结构负担，即建即跑。
* **规格 B：Standard（四顶层资产与生命周期治理架构 · 标准工程 - 官方推荐）**
  - **适用场景**：常规商业化应用、前后端分离工程、全栈 Web/移动端、有持续版本迭代的独立项目；
  - **架构本质**：**四大顶层独立资产分立 + 生命周期闭环**。
    1. 顶层分工：`AGENTS.md`（宪法底线）+ `ARCHITECTURE.md`（拓扑与集中 ADR）+ `CONTEXT.md`（纯净业务事实）+ 全局单真理源 `PHILOSOPHY.md`；
    2. 物理秩序：`docs/` 100% 留给用户 PRD，`.agents/` 收揽专名字典（`proper-nouns.md`）与云归档指针（`cloud-archive.md`），沉淀台账则全域统收于 `~/.agents/custodian/cd-weekly-log.md`；
    3. 运行支撑：打通基于 `/cd` 的会话知识脱水与基于 `/zj` 的定期审计保洁。
* **规格 C：Heavy（多域强防腐边界与宏观路由架构 · 工业级大型系统）**
  - **适用场景**：企业级 Monorepo、多产品挂载复杂系统（如“理论决策研究 + 交付软件平台”双产品挂载）、跨域大型科研仿真工程；
  - **架构本质**：**多域强防腐边界 + 宏观多入口路由 + 专有领域扩展技能挂载**。在 Standard 基础上追加：
    1. **多域强防腐边界与交付红线 (`docs/product-boundary.md`)**：明确定义多产品/多模块间的挂载关系、决策链防线与能力真伪防线，严禁跨域造假与越权串味；
    2. **多入口宏观路由大地图 (`AI_START_HERE.md`)**：为跨 AI 异步团队提供全局入口指引，根治大型项目新接手 AI“盲人摸象”的深层迷航；
    3. **本地专属领域扩展技能 (`.agents/skills/`)**：挂载当前工程专属的高壁垒领域工具（如核算门禁、空间建模、仿真套件），依托标准 JIT 规范实现复杂规约的渐进式按需加载。

### ⚡ 四大核心驱动能力 (Core Capabilities)

Relay 采用统一的极简命令驱动日常工程协作，支持拼音缩写与自然口语双向触发：

| 指令 / 快捷别名 | 技能名称 | 核心能力与心智 |
| :--- | :--- | :--- |
| **`/relay`** 或 `relay.py init` | **【初始化与开箱】** | 由 CLI 按体量生成骨架；默认保护已有文件；存量工程可用 `--dry-run` 预览后接入。 |
| **`/jp`** 或 `纠偏` | **【思维校准罗盘】** | **双模引擎**（前置预防 + 后置纠偏），对照正向哲学纠偏，破除非黑即白，直接输出可用代码。 |
| **`/cd`** 或 `沉淀` | **【知识脱水与回流】** | **会话严格验真**；仅提炼【现象 - 根因 - 最小解法】；**确认先行，严禁直接修改，必须先列清单让人确定**；确认后安全落盘登账。 |
| **`/zj`** 或 `周检` | **【全局自检与保洁】** | 自动审计台账；督促超长大文档建立里程碑索引；提请完结大资产迁移外部存储留单行指针；零通胀事实汇报。 |

#### 技能详细说明：
* **`/relay`（初始化与生命周期）**：使用 `relay.py init` 或由 AI 按该命令执行，按可观察的工程体量选择规格（Lite / Standard / Heavy）；需要预览时显式传入 `--dry-run`，默认保留已有同名文件。
* **`/jp`（思维纠偏双模引擎）**：
  - *前置预防*：启动复杂重构或深水区任务时附带 `/jp`，AI 开局即装载正向思维，客观权衡收益与代价；
  - *后置校准*：发现 AI 输出出现反向辩白、教条主义、过度设计或从一个极端滑向另一个极端的“二极管摆动”时，输入 `/jp`，立即在思维链中对照正向支柱重新组织交付。
* **`/cd`（知识脱水与资产回流）**：
  - **确认先行协议**：AI 严格执行两阶段安全落盘协议：第一阶段仅提炼并呈送待审草案（类别、目标路径、拟追加内容与精确 Diff），获得用户明确确认后，第二阶段方可执行物理写入与登账；
  - **宪法只读红线**：严禁 AI 自主修改 `AGENTS.md`（仅人工可写），新规约一律沉淀为 JIT 技能、ADR 或测试用例；
  - 必须在终端实跑通过，以真实运行事实为准绳；
  - 严禁控制台日志入库，落盘仅保留极简单行或最小解法；
  - 由宿主 AI 按确认协议向全局总控中枢 `~/.agents/custodian/cd-weekly-log.md` 统一双写登账（明晰标注项目标识与物理路径）；Relay CLI 不伪装成后台任务执行器。
* **`/zj`（定期保洁与周巡检）**：
  - 穿透项目检查台账，核查历史长文档是否维护里程碑索引；
  - 督促大体积归档资料迁出至外部网盘/NAS，本地仓库仅留轻量检索指针；
  - 健康时仅汇报 2 行事实，不强造无意义的虚假改进建议。

### 🎯 四大立竿见影的确定性收益 (Concrete Benefits)

使用 Relay 后，您的开发流将获得四项确定性的质变提升：

* ⚡ **减少常驻规则负担**：将架构、业务和领域规约放入按需读取的文件；实际上下文收益取决于客户端和项目内容，不作固定百分比承诺。

* 📦 **归档策略可选**：提供轻量指针模板，但不会自动移动或删除用户资产。

## 🎮 第二部分：用户极简操作手册 (User Operations Guide)

### ⏱️ 1 分钟极速安装与部署 (Installation)

Relay 支持从“全局资产安装”到“单项目零安装”的接入方式。确定性初始化由仓库内的标准库 CLI 提供，AI 技能文件负责协作规约与按需提示。

#### 姿势 A：可审计安装（推荐）
克隆本仓库后，运行对应平台的一键安装脚本，自动将核心思想、台账中枢与驱动技能部署至 `~/.agents/`：
```bash
# 克隆仓库
git clone https://github.com/zhuangyan-edu/relay.git
cd relay

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File .\install.ps1

# macOS / Linux
bash ./install.sh
```

安装器默认不会覆盖已有文件；先用 `-DryRun` / `--dry-run` 预览，只有明确指定 `-Force` / `--force` 才会覆盖冲突（可同时使用备份选项）。安装包完整性可用 `-Check` / `--check` 验证。

#### 确定性 CLI（无需第三方依赖）

```bash
# Windows PowerShell
py -3 "$HOME/.agents/relay.py" init . --profile auto
py -3 "$HOME/.agents/relay.py" init . --dry-run
py -3 "$HOME/.agents/relay.py" audit .
py -3 "$HOME/.agents/relay.py" sweep --dry-run

# macOS / Linux
python3 "$HOME/.agents/relay.py" init . --profile auto
python3 "$HOME/.agents/relay.py" init . --dry-run
python3 "$HOME/.agents/relay.py" audit .
python3 "$HOME/.agents/relay.py" sweep --dry-run
```

CLI 默认保留目标目录中的同名文件，并把初始化元数据写入 `.relay.json`（Lite）或 `.agents/relay.json`（Standard/Heavy）。全局项目注册写入 `~/.agents/custodian/projects.json`；Markdown 台账仅作人工阅读索引。

#### 姿势 B：单文件零安装接入（最轻量）
如果你**不想碰任何全局配置**，只想在当前项目享受 Relay 的接力能力：
直接将本仓库 `templates/AGENTS.md` 拷贝到项目根目录；是否自动读取由所用客户端决定，也可以通过客户端的项目规则入口显式引用。

### 🔌 各 AI 客户端接入方式 (Client Bridging)

如果你在不同工程中主力使用不同 AI 客户端，只需 1 行指向核心宪法：
* **Claude Code**：在项目根目录 `CLAUDE.md` 中写一行：`See AGENTS.md`
* **Cursor**：在项目根目录 `.cursor/rules/relay.mdc` 中引用 `AGENTS.md`；不要依赖已弃用的 `.cursorrules`。

* **Codex / Gemini / Antigravity / WorkBuddy**：按各客户端当前版本的项目规则入口引用 `AGENTS.md`；是否自动读取外部 `~/.agents` 文件取决于客户端，Relay 不假设存在统一标准。

### 🕹️ 日常开发 4 步操作指南 (Daily Operations)

您只需要记住 4 个最自然的日常操作：

#### 1. 开局初始化：`relay.py init`
进入你的工作项目目录，直接对任何 AI 下达指令：
```text
用 relay 初始化项目
```
CLI 将根据项目复杂度选择规格（Lite / Standard / Heavy），生成骨架并更新机器可读的项目注册表；需要 Heavy 的边界文档或自定义技能时，再由项目维护者补充真实内容。

#### 2. 思维纠偏：`/jp`
发现 AI 陷入“过度设计”、“教条洗白”或“反向二极管极端（被否定后报复性走向另一极端）”时，输入：
```text
/jp
```
AI 立即在思维链中对照正向哲学重新自查，直接交付可用代码。

#### 3. 知识沉淀：`/cd`（两阶段：列清单 -> 确认 -> 写入）
攻克关键技术暗坑或完成阶段里程碑时，输入：
```text
/cd
```
* **第一阶段（清单待审）**：AI 严格执行两阶段协议，仅提炼【现象 - 根因 - 最小解法】并连同拟写入的目标物理路径完整呈送待审；
* **第二阶段（确认落盘）**：收到您的明确指令（如“确认”、“同意”）后，AI 方才安全写入对应物理文件，并按台账规则记录变更。

#### 4. 定期保洁：`/zj`（依据工作区自动分流）
周末或结项时，输入：
```text
/zj
```
* **在业务项目工作区敲**：执行【单项目就地保洁】，清理当前项目的 `scratch/`，清算本项目的 `.agents/cd-weekly-log.md` 待审条目，提示大文件移云，安全隔离不越权；
* **若要全机跨项目大巡检**：**必须在 IDE 中打开 `~/.agents/` 专属工作区**，敲 `/zj`。AI 自动切换至“全机总管”视角，穿透盘点全机所有登记项目并输出全局汇总简报。

### 🛡️ 存储介质自选与纯静态降级 (Zero-Skill Fallback)

#### 1. 归档介质完全由您自由指定
Relay 绝不强绑任何特定网盘或第三方服务：
- 项目初始化时，您可自由指定归档存储位置（Google Drive 团队盘、OneDrive、本地 NAS、阿里云盘、S3 或本地独立备份盘）；
- 本地 `.agents/cloud-archive.md`（或既有 `gdrive-cloud-archive.md`）仅作为纯文本的“单行检索指针表”，支持团队多人协同查阅。

#### 2. 如果 AI 不支持 Skill 插件怎么办？（纯静态降级方案）
这是 Relay 最关键的鲁棒性底牌：**Relay 的底层基石是“纯 Markdown 文件规范”，而不是执行代码！**
- 即使在**网页端 ChatGPT、API 脚本、离线开源模型或普通编辑器**等完全不支持 Skill 的环境中：
  - 四大顶层资产（`AGENTS.md`、`ARCHITECTURE.md`、`CONTEXT.md`）都是标准 Markdown，所有模型天生就能读懂和维护；
  - 遇到需要沉淀或纠偏，直接用自然语言交流：
    - *“把刚才解决的 bug 脱水写入 .agents/cd-weekly-log.md 的待审表格，先列出清单由我确认”*；
    - *“对照根目录架构说明，检查当前方案是否破坏模块边界”*；
  - **技能文件是可选的协作规约**；没有客户端技能插件时，仍可手动阅读和维护这些 Markdown 文件。

### 🏛️ 四大独立顶层资产与物理隔离 (Top-Level Assets)

Relay 将工程资产做出了最高清晰度的物理切分，各司其职，互不污染：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        四大独立顶层资产 (Top-Level Assets)               │
├───────────────────┬───────────────────┬─────────────────┬──────────────┤
│   PHILOSOPHY.md   │  ARCHITECTURE.md  │    AGENTS.md    │  CONTEXT.md  │
│   【核心思想】    │   【系统架构】    │  【微内核宪法】 │ 【业务现状】 │
├───────────────────┼───────────────────┼─────────────────┼──────────────┤
│ 跨 AI 思考与权衡  │ 系统拓扑、技术栈  │ 极简两行微内核  │ 业务逻辑事实 │
│ 预装确立六大支柱  │ 集中收拢 ADR 决策 │ + 项目独有规约  │ 产品功能状态 │
│ 全局唯一单真理源  │ 明文 AI 维护协议  │ 零提示词通胀    │ 纯净业务事实 │
└───────────────────┴───────────────────┴─────────────────┴──────────────┘
```

1. **`PHILOSOPHY.md`（灵魂 · 全局单真理源）**：
   * 存放在全局 `~/.agents/PHILOSOPHY.md`，全机**只有这唯独一份**；
   * 预装经过实战淬炼的**六大工程核心思想**；
   * 本地项目绝不复制代码！改动 1 次全机所有项目秒级同频受益，彻底终结多项目同步噩梦。
2. **`ARCHITECTURE.md`（骨架 · 本地独享系统架构）**：
   * 项目专属技术全景，整合系统拓扑、模块依赖与前后端解耦边界；
   * **彻底消灭零碎的 ADR 碎片目录**：在一个连贯日志中集中记录选型因果（为什么选、放弃了什么、锁定了什么）；
   * 附带明文的《AI 架构维护协议》，让后续接力的任何 AI 都能直接就地维护架构。
3. **`AGENTS.md`（宪法 · 微内核 + 本项目核心规约）**：
   * 包含全域统一的“两行极简微内核”与“本项目核心规约 (Project Invariants)”；
   * **项目唱主角，展现自身特色**：由项目自主陈述不可动摇的底线规则（算法边界、核心场景、契约优先、类型禁令等），字字管用。
4. **`CONTEXT.md`（血肉 · 纯净业务上下文）**：
   * 100% 专注业务产品逻辑、用户旅程与当前功能状态，绝不掺杂任何技术架构、工作流或 AI 运维杂质。

```text
                                     （周检与沉淀总台账统收于全局 ~/.agents/custodian/cd-weekly-log.md）
```

### 📜 极简微内核宪法标准 (The Two-Line Standard)

为了根治提示词恶性通胀、破除负向催眠，Relay 确立了面向全机所有 AI 客户端的**统一两行基线**：

```markdown
# Relay Agent Constitution

- **核心思想**：客观求真、实效权衡、两端取优、纯正向聚焦（详见 ~/.agents/PHILOSOPHY.md）。
- **接力心智**：面向跨 AI 异步团队交付持久化、可运行的代码与文档。
```

> **设计要诀**：
> 1. **原词直达**：直接使用 4 个核心思想原词，零多余排比解释，上下文消耗趋近于零；
> 2. **纯正向表达**：一字不提“严禁”，从根源消除粉象效应；
> 3. **单向指针**：将具体思想解析收敛于全局单真理源 `~/.agents/PHILOSOPHY.md`，按需深读，不占常驻提示词；
> 4. **原生人设完整保护**：有原生特色的 AI（如 WorkBuddy K2 原生人设）100% 完整保留，通用底座与领域基因有机共生。

### 🧭 用户自主决定的三级治理阶梯与范围控制 (Three-Tier Governance)

Relay 坚决杜绝“全家桶式强行捆绑”——是否接管全局配置，选择权 100% 属于用户：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        用户自主裁决的三级治理阶梯                       │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 3：系统全局配置托管 (Global System & AI Alignment)                │
│   • 一体化搞定全机 6 大 AI 客户端（Claude/Cursor/Codex 等）系统提示词  │
│   • 部署全机单真理源 ~/.agents/PHILOSOPHY.md 与全局共享技能库          │
│   • 用户裁决：是否授权 Relay 一并托管并对齐全机 AI 全局配置？           │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 2：全机项目资产总控 (Machine-Wide Portfolio Custody)              │
│   • 盘点已登记工程，统一登记入 ~/.agents/custodian/projects.json     │
│   • 周检 (/zj) 站在全机高度，穿透所有项目做防腐保洁、跨库暗坑聚类、移云│
│   • 无论项目在 C 盘、D 盘还是其他目录，全盘资产一目了然                │
├────────────────────────────────────────────────────────────────────────┤
│ 阶梯 1：单项目轻装接入 (Single Project Isolation)                      │
│   • 仅对当前单次任务/小工具生成 AGENTS.md 或标准资产                   │
│   • 绝对物理隔离，不触碰电脑上其他项目，不改动任何系统全局配置         │
└────────────────────────────────────────────────────────────────────────┘
```

> **⚡ 核心铁律：初始化只改用户明确指定的范围 (Scoped Initialization)**
> - `relay.py init` 只写当前项目的选定模板，并将项目登记至全局 `projects.json`；它不会隐式改写其他客户端配置。
> - 已存在的不同内容默认报告冲突并保留，只有显式传入 `--force` 才覆盖文件；重复初始化不会重写元数据。
> - 全局巡检由显式的 `relay.py sweep` 执行，不依赖模型“自行记得”运行后台任务。

### 🌐 全局总控中枢 (`~/.agents/custodian/`)

Relay 在用户主目录建立了面向全机所有工程与 AI 客户端的全局总控中枢：

```text
~/.agents/
├── PHILOSOPHY.md                 # 全机唯一核心思想真理源
├── custodian/                    # 【全局总控中枢】

│   ├── projects.json             # 机器可读项目注册表（CLI 的权威输入）
│   ├── projects.md               # 人工阅读的项目台账模板
│   ├── ai-agents.md              # AI 客户端监管台账（统管 Claude, Cursor, Codex 等系统提示词）

└── skills/                       # 全局核心驱动技能包
```

1. **`cd-weekly-log.md`（全局沉淀总台账）**：全机统一汇聚各工程会话知识脱水与避坑实录，带项目标识与物理路径，消除多项目周检到处找台账的碎片化成本；

3. **`ai-agents.md`（AI 客户端监管台账）**：统一监管全机 AI 客户端的提示词规范，既守牢极简底线，又保护原生特色；
4. **`reports/`（审计周报归档）**：沉淀历次全局巡检的脱水简报，事实清楚、无冗余通胀。

### 🎯 六大工程核心思想 (The 6 Pillars of Philosophy)

Relay 坚守六大纯正向支柱（详见 [PHILOSOPHY.md](PHILOSOPHY.md)）：

1. **全域受益 (Global Benefit)**：单点突破提炼后母版同步受益，所有项目共享免疫抗体；已完结的历史重型资产规范归档云端，本地仓库轻量敏捷。
2. **实效权衡 (Pragmatic Trade-offs)**：繁简自适，按实际工程体量自主裁决复杂度；**按需建立，物尽其用，杜绝冗余**。既有容器能承载的内容直接合并，消除无价值派生文件。
3. **两端取优 (Optimal Balance & Trade-offs)**：
   * **杜绝矫枉过正，不走反面极端**：当用户提出反向否定（如“不要某物”、“太繁琐”）时，精准识别否定边界，只切除多余杂质并稳守有效基石；坚决杜绝因被否定而过度反应、滑向对立极端的二极管报复性摆动；
   * **因地制宜，合理权衡**：不搞绝对化的非黑即白，寻求综合收益最高、副作用最小的务实解；
   * **无损继承与领域共生**：全局统一与局部特质并存，通用底座与领域基因有机共生，拒绝机械式一刀切。
4. **客观求真 (Fact-Based Objectivity)**：
   * **独立客观，不盲从迎合**：立足技术规律与客观事实，不因用户的主观推测或倾向性建议而盲从附和；
   * **以真实证据为凭据**：以代码实际运行结果与客观证据为准绳，就事论事，敢于直言指出技术隐患。
5. **纯正向聚焦 (Affirmative Delivery Focus)**：
   * **肯定陈述**：表达聚焦于系统具备的能力、客观数据与具体实施路径；
   * **直奔交付**：精力 100% 倾注于代码落地与实际推进，直接给出可用方案与运行结果，消除防御性免责与反向辩白。
6. **融贯自洽 (Dynamic Coherence)**：原则相通互保，动态统一于工程交付实效；分层索引互为闭环，让体系既清爽轻量，又事实可考。
