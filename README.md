# Relay 🏃‍♂️

> **The Minimalist, Zero-Overhead, Self-Evolving Agent Framework for Relay Coding.**  
> 面向跨 AI（Claude / Cursor / Gemini / Codex / GPT）异步接力与自进化的极简敏捷工程套件。

> `Version: 3.6.0` · `License: MIT` · `AI-Native: Claude | Cursor | Gemini | Codex | WorkBuddy` · `Philosophy: Affirmative & Lossless`

---

## 💡 为什么诞生 Relay？

在现代 AI 辅助编程与跨模型异步协作中，开发者普遍遭受四大结构性折磨：

1. **粉象回潮与思维瘫痪**：系统提示词充斥着“严禁做X”、“冷酷审视”、“严禁谄媚”，负向催眠诱发大模型陷入自我怀疑与防御性内耗，光写免责辩解却迟迟不给代码；
2. **多项目同步地狱**：每个项目根目录都拷贝一份大同小异的规范文件；一旦原则演进，必须手动同步本机数十个代码库；
3. **提示词恶性通胀**：把工具配置、沙盒说明一股脑塞进全局提示词，白白浪费 Token，还给 AI 套上沉重的枷锁；
4. **业务文档被肆意污染**：AI 的自检流水账、专名映射表被粗暴塞入 `docs/`，与用户原本干净的需求文档、PRD 和 `.docx` 严重撞车冲突。

**Relay（接力）用一套极其克制的“全局单真理源 + 极简微内核 + 物理隔离 + 双中枢托管”模型，彻底击碎以上乱象，让代码库与跨 AI 团队像传接力棒一样流畅自进化。**

## 🏛️ 四大独立顶层资产（各司其职，互不污染）

Relay 将工程资产做出了最高清晰度的物理切分：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        四大独立顶层资产 (Top-Level Assets)               │
├───────────────────┬───────────────────┬─────────────────┬──────────────┤
│   PHILOSOPHY.md   │  ARCHITECTURE.md  │    AGENTS.md    │  CONTEXT.md  │
│   【核心思想】    │   【系统架构】    │  【微内核宪法】 │ 【业务现状】 │
├───────────────────┼───────────────────┼─────────────────┼──────────────┤
│ 跨 AI 思考与权衡  │ 系统拓扑、技术栈  │ 极简两行微内核  │ 业务逻辑事实 │
│ 预装确立六大支柱  │ 集中收拢 ADR 决策 │ + 项目独有规约  │ 产品功能状态 │
│ 全局唯一单真理源  │ 明文 AI 维护协议  │ 零提示词通胀    │ 纯净业务事实 │
└───────────────────┴───────────────────┴─────────────────┴──────────────┘
```

1. **`PHILOSOPHY.md`（灵魂 · 全局单真理源）**：
   * 存放在全局 `~/.agents/PHILOSOPHY.md`，全机**只有这唯独一份**！
   * 预装经过实战淬炼的**六大核心思想**（全域受益、实效权衡、两端取优、客观求真、纯正向聚焦、融贯自洽）；
   * 本地项目绝不物理复制代码！改动 1 次全机所有项目秒级同频受益，彻底终结多项目同步噩梦。
2. **`ARCHITECTURE.md`（骨架 · 本地独享系统架构）**：
   * 项目专属技术全景，整合系统拓扑、前后端解耦边界；
   * **彻底消灭零碎的 ADR 碎片目录**：在一个连贯日志中集中记录选型因果（为什么选、放弃了什么、锁定了什么）；
   * 附带明文的《AI 架构维护协议》，让后续任何 AI 都能有据可依、集中直接更新架构。
3. **`AGENTS.md`（宪法 · 微内核 + 本项目核心规约）**：
   * 包含“两行极简微内核”与“本项目核心规约 (Project Invariants)”；
   * **项目唱主角，展现自身特色**：由项目根据自身业务本质（算法边界、核心场景、契约优先、类型禁令等）自主陈述不可动摇的底线规则，字字管用，拒绝教条洗白。
4. **`CONTEXT.md`（血肉 · 纯净业务上下文）**：
   * 100% 专注业务产品逻辑与功能现状，再也不会被技术架构、工作流或 AI 运维杂质所干扰。

## 🔒 物理隔离：业务归业务，Agent 归 Agent

在项目文件树中，Relay 实行绝对的边界隔离：

```text
📁 docs/                          ──► 【100% 留给开发者】业务方案、PRD、文本与 docx，AI 绝不占用！
📁 .agents/                       ──► 【Agent 专属内部空间】彻底隔离内部支撑：
   ├── cd-weekly-log.md           ──► 周期沉淀与周检审计台账（含纪元索引表）
   ├── proper-nouns.md            ──► 2~4 字专有名词字典（支持缺页自愈）
   ├── gdrive-cloud-archive.md    ──► 云归档检索墓碑表（迁出重型资产至网盘）
   └── skills/                    ──► 本项目专有的领域级技能
```

## 🌐 全局中枢工作区 (`~/.agents/custodian/`)

Relay 为跨项目管理与跨 AI 统一治理提供了全局中枢：

1. **`projects.md`（项目注册总台账）**：记录全机所有已装载 Relay 的项目物理路径与周报寻址；
2. **`ai-agents.md`（AI 客户端提示词总台账）**：统一监管全机 AI 客户端的系统提示词，严守统一底线并保护原生人设；
3. **`reports/`（审计周报归档）**：定期沉淀跨项目、跨端全局自检汇总报告。

## ⚡ 三大核心驱动技能（指令与中文映射）

Relay 采用统一的极简命令驱动日常开发，支持拼音缩写与自然中文口语双向触发：

### 1. `/jp` —— **【纠偏】** 思维校准罗盘（双模引擎）
* **前置预防模式**：在启动复杂任务或重构时，带入 `/jp`，AI 开局即装载正向哲学，客观权衡利弊，直接交付可用代码；
* **后置校准模式**：发现输出出现教条、过度设计或反向辩白时输入 `/jp`，立即在思维链中对照清单重构，直接输出可用成果。

### 2. `/cd` —— **【沉淀】** 知识脱水与回流引擎
* **会话严格验真**：必须在终端真实跑通通过；
* **严禁日志污染**：落盘仅保留脱水后的【现象 - 根因 - 最小解法/单行命令】，严禁控制台日志入库；
* **自动登账**：自动向 `.agents/cd-weekly-log.md` 追加单行待审，具备全域价值的提请晋升母版。

### 3. `/zj` —— **【周检】** 全局自检与跨项目保洁中枢
* **中枢定点穿透**：依据 `custodian/projects.md` 自动穿透本机所有项目，按表索骥定点审查质量；
* **清晰索引与断舍离**：核查历史长文档是否维护纪元归档索引，提请完结大资产迁移至云盘并留单行墓碑；
* **零通胀简报**：健康时直报 2 行事实，不强造虚假建议。

## 🚀 3 秒快速开箱：`relay init`

在新项目目录对任何 AI 说：`用 relay 初始化项目`（或 `relay init`），选择体量规格，精准落盘：

| 规格级别 | 适用场景 | 落盘清单（精准可数，杜绝多余） | 特点 |
| :--- | :--- | :--- | :--- |
| **1. Lite** | 单次爬虫、简单数据脚本、算法 Demo | **仅 1 个文件**：`AGENTS.md`（两行微内核） | 零 docs、零多余配置，单文件轻装上阵。 |
| **2. Standard**<br>*(推荐)* | 前后端独立 Web、小程序、标准库工程 | **共 4 份核心文件**：<br>1. `AGENTS.md`<br>2. `ARCHITECTURE.md`<br>3. `CONTEXT.md`<br>4. `.agents/` 专属支撑三件套 | 业务 `docs/` 完全留白，开箱即拥有完整自进化能力。 |
| **3. Heavy** | 跨端跨学科工业级大型系统 | **在 Standard 基础上追加**：<br>+ `docs/product-boundary.md`<br>+ `AI_START_HERE.md`<br>+ 本地 `.agents/skills/` 目录 | 满足工业级多产品搭载与复杂边界协同。 |

## 🎯 核心工程哲学 (Philosophy)

Relay 坚守六大纯正向支柱：

1. **全域受益**：任何单点突破提炼后母版同步受益，历史重型资产移云协同。
2. **实效权衡**：繁简自适，按实际需求决定尺度；**按需建立，物尽其用，杜绝冗余**。
3. **两端取优**：**合理权衡，杜绝非黑即白**；面临反向否定时，精准识别边界，**坚决杜绝矫枉过正走向反面极端**。
4. **客观求真**：**独立客观，不盲从迎合用户的偏向与主观臆测**；以代码客观证据为准，敢于直言指出技术隐患。
5. **纯正向聚焦**：肯定陈述系统能力与行动方案，100% 专注代码落地推进，破除粉象效应。
6. **融贯自洽**：原则相通互保，动态统一于工程实效，决策逻辑高度一致。
